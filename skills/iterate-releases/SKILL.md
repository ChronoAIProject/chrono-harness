在用户授权的仓库和发布范围内推进到真实采用；没有授权的其他仓库不自动纳入。先读各仓库的 AGENTS 与 host_context，定位当前发布、安装、检查和生命周期登记。此 skill 不授予额外权限，也不要求再次确认已经授权的发布与合并。

在 chrono-harness 中，以当前检出根的 `docs/release-iteration.md` 为迭代验收来源；`docs/release-ci.md` 管发布及恢复，`docs/distribution.md` 管安装，`docs/examples.md` 确定四个现役下游。此 skill 的唯一维护源是 `.chrono-harness/instructions/catalog.json` 的 `core.release-iteration`；manifest 登记的仓库 skill 和个人目录都是生成或安装副本。修改登记源后执行正式指令生成入口，再同步个人副本。没有本地检出时先取得已授权仓库的固定修订，不凭移动网页代替候选输入；其他产品先定位其等效合同，不套用本仓仓库名或入口。

先完成一个测试版，再迁移下游。固定成功落地 CI 的源码 SHA、run 和原 attempt，检查是否已有该身份的自动发布；接续它，只有确无原运行才显式触发 preview。发布工作流列表中的 head 不一定是发行源码，核原 CI、回执、清单和标签的共同身份。等待原运行及两平台安装结果，核公开资产后才把版本交给下游。

手动派发前同时固定工作流修订：`source` 只控制检出，`--ref` 控制 GitHub 实际执行的工作流。正式版使用已核验、指向同一源码的最终测试版标签作为 `--ref`，并核新 run 的工作流 head。移动的 dev 若已改 needs／downloads，不能用新拓扑执行旧候选。发现实际派发输入不符时，保留差异和原件，终止尚未公开的错误运行并等待最终状态，再从匹配的固定 ref 派发；不移动标签，不把取消后的缺产物错误解释成产品回归。自动触发的工作流修订也须核适用性，不能只看源码参数。

采用带工作流预检的新候选时，核两平台 frontend 的 `workflow` 观察及原 `workflow.json`。不同提交可含同一个工作流 blob，不能仅因 head 不同就重建；字节不同、缺绑定或 Git 失败时，保留失败原件并按负责文档从固定 ref 恢复。旧候选没有该观察，不能补写成已经执行。

逐个比较下游已采用版本与候选的 schema、CLI、安装声明、工具绑定、生成源和宿主定制。用候选安装器显式 adopt 固定版本，再使用下游登记的入口生成和验证；不只替换版本字符串，也不以 init 覆盖定制。保持业务测试和初始清单合同，从各自最新目标分支隔离迁移，核 PR 实际合并、落地 SHA 和落地 CI。自动合并不可用时沿下游已登记的现有权限入口完成交付，不申请新权限或另加确认；无法修改的远端配置保留精确限制。

检查期间固定该检出的 HEAD 和已跟踪输入，等原任务结束再提交新修复；输入漂移的失败不能赋给新候选。宿主迁移的短命令、平台政策、旧输出所有权、上传根及 runner 可用性边界按负责文档核对。精确 Git pin 从本候选 bootstrap 原回执更新，保持各下游定制。

失败先读原 stdout／stderr／退出及实际输入，在产生问题的负责处修复。断言只显示预期而丢失实际返回时，先在原断言补输入与完整返回诊断；旧原因保持未知，不由新候选成功反推。产品修复重新走 dev、测试版和受影响下游验收；下游局部失败不阻断独立工作。保留原失败和恢复条件，相同症状需要相同处理第二次时修复产生处，不作第三次盲重试。复用现有发布者的 draft 续传，不 clobber 公开资产、不移动版本标签、不改成功要求。

PR 等待用例先核首次 API 的原退出。未取得有效远端观察的超时须按 PR 合同保持 unknown，取得 pending 观察后的到期另核；不能把任意退出 2 当作合格结果。按原生产者回执核实际派发，保留原期限和原生等待输入；替身自身的部分日志不能代替完整调用回执。

会合回归先保留已等待终结的驱动进程返回，再解释控制线程的 socket 断言。`poll` 到期不读取 errno；内层 CI 静默超时复用测试宿主已有阶段日志政策和原输出上限，沿原期限验收。诊断补齐只提高可观察性，不能报告旧超时已修复。

启动失败先核意图和原系统错误，不能当作业务断言失败。`ETXTBSY` 要审查可执行输入的写入／描述符生命周期；并发测试复用不可修改的已封口执行物，内容变异使用独立副本。补启动前意图与失败回执，不以重试、减线程或加期限掩盖。生产复制／解包后的执行仍须原生发布验收。

最后关闭与即时回收断言遇到元数据繁忙时，核原进度并复用已有单用例隔离，排除无关 fork 继承租约的干扰；保留父套件默认并发、维护轮数及预算，具体持锁者缺证仍保持未知。

命令替身也计入实际身份校验和执行成本。超时先核原回执及实际落地源码中的替身依赖／体积和各阶段读数；并行迁移后的工具闭包不能由原 feature 或 integration 代证。简单高频接口复用已有标准库小替身，移除仅为较大替身所需的设置，保留当前 mock 边界及 argv、输入、输出与退出合同。不改构建配置、线程、用例或期限来消除失败；新执行物仍走原 canonical 与原生发布验收。

fetch 替身超时还要按迭代文档核共享对象的重复写入与本地不可变对象复用，先用回归证明问题，再验缺失输入和浅历史边界。不同阶段的超时分别保留原因与测量，不能仅凭症状相同合并归因。

本地超时诊断按迭代文档选择 canonical 单元入口；同名 operation 的其他入口可能采用不同期限。固定失败候选和采样身份，等检出创建完成后再导入，保留原现场与后续 DELTA 验收。

中断回归未取得握手时，核 wrapper 是否仍在准备输入；复用已有受管等待入口及原登记期限，先取得使用方握手再实施中断。不能把测试主动提前杀死准备进程解释成产品恢复失败，仍保留提前退出原件与未知使用保护断言。

握手已取得后再超时，按迭代文档核同一期限内的准备与维护，保留实际维护返回和阶段耗时；不由缓存消失推断提前清理活租约。按登记选择包含失败用例的单元，未执行的用例不能由绿色结果代证。

缓存独立地址的中断用例还须核原探测期限内的完整独立计划与维护，等待驱动终结并保留完整返回和累计阶段耗时。`kill` 的进程不存在错误不能解释进程结束原因；沿原期限、线程和断言定位实际负责处。

已有进程日志的握手前超时，先分开启动前准备和子进程运行。按负责流程审计重复读取／校验，复用原引擎的启动前身份核对时仍保留缓存及返回后漂移保护；不从前置阶段慢直接推断哈希或死锁，不改变期限与线程来通过。

独立计划返回过晚时，复用已采用的有限 debug 阶段日志，按相同 CLI PID／尝试区分探测、输入返回、结果封存、原件核验、计划发布和依赖绑定。累计墙钟只在同一函数起点内作差，不能把文件 mtime 或总耗时当作 CPU 根因。原任务终结后核完整输出和日志，再修已证实的重复工作；记录阶段不等于修复旧超时。判法和成本边界由迭代文档负责。

年龄回归的多阶段输入按负责文档安排：复用阶段不与删除条件抢时间，进入删除阶段显式采用原阈值，核创建时间未重置并保留全部保全、复用及删除断言。业务保留政策与执行时限分别核对，不改时钟、账本或执行期限。

恢复同一发布时，先等原运行真实终结，再按显式依赖和仍有效的原件选择最小重跑。新 job ID／当前 attempt 可能只是沿用结果，须核选中 artifact 和原回执的实际生产身份。部分重跑仍受平台总时间窗约束；原输入全部过窗时刷新受影响平台的 frontend 及依赖闭包，不只重跑 collector，也不提高预算。控制面 `in_progress`、取消 409 或观察 502 均须保留原状态并接续等待，不能据此重复派发。具体判法由发布恢复文档维护。

满足负责文档的全部稳定条件后才选择 stable；正式版本须与固定源码内计划一致。计划变动产生新候选，先为它发最终测试版并验收。发布正式版后核公开状态、标签源码、全部资产及两平台安装，再迁移下游到正式版并核实际落地。只证明到哪一阶段，就报告到哪一阶段；unknown 不算稳定。

本仓已采用 `dev`／`main` 合同：正式发布前按迭代文档的唯一晋升入口，将 `main` 非强制快进到最终测试版的完整源码 OID 并回读核对。原 dev CI 与最终测试版身份保留；不制造新合并提交、不移动标签，也不把分支晋升当作公开发布。

采用晋升合同的候选还须显式固定最终测试版发布的 run／attempt。按负责文档核成功原运行、实际生产 attempt／artifact ID、原平台时间窗、工作流字节、原 CI 和公开资产，再由现有发布者消费原包并生成新的正式输出。原回执保持测试版身份，正式回执记录来源；同源码不自动取得复用资格。缺失、过期或损坏原件阻止晋升，不回退重建、不改写旧记录。分别核正式版实际执行的作业、继承的原验证与新安装结果；成本比较沿用相同单位和窗口。

选最终候选时按负责文档核仍有效的失败；scoped CI 的后续绿色不能清除未选中且仍由该源码继承的失败。核相关修复及适用原件，再判断稳定，不靠无关通过或全仓重跑代替。发布来源 CI 与安全扫描各核已登记工作流、固定源码和结论；按迭代文档核 CodeQL 的动态事件，不把来源 CI 的 push 条件套给安全扫描。

文件写入成功不代表结果已封存。封存绑定失败时，核原阶段、结果绑定与恢复引用；用可控的预算边界回归验证同一原件续接，保留真实内容错误。报告字节删除、元数据引用解绑和最终地址退役分别核实际状态与所持能力；字节缺失或一轮结束不表示全部完成。续接回归保留替换条目保护、原件、原结果和仍在使用的引用。处理方式见负责流程，不以提高预算或重复发布掩盖部分完成；缺原状态的旧失败仍保持未知。

检查通过而原生作业在缓存封存失败时，按负责流程核实际选中操作及缺失产物；步骤成功不能证明所有静态缓存都已生成。缺失的可选产物由缓存所有者记录并停止保存，类型、权限和内容错误继续失败。不补跑无关测试、创建空目录或关闭核验；整轮 CI 失败仍不可交给发布者。

采用前从下游现役安装声明读取完整工具映射；adopt 后逐项比较工具及安装位置，不能凭记忆手列子集。版本、manifest、两平台 installer 和工具成员分别核对；宿主上下文若仍写旧版本，保持分发声明为实际安装权威并修正过时说明。

验证分类必须绑定实际进入候选编译／证明的源码。只登记另一个没有包含受影响文件的根不能取得覆盖；新增的边界预期应使用真实运行的同源实现，明确局部证明与原生 IO 测试各自的范围，不能通过改成 data 或关闭门控消除缺口。新接入证明根的源码须能由实际证明编译器的 edition 解析，原生专属 cfg 不豁免语法解析；在负责源码使用等价语法，保留原证明入口。

同一边界同时在 Verus 与普通 Rust 执行时，纯证明断言在普通编译中可能被擦除。复用现有带 `requires` 且在条件为假时实际 panic 的预期函数，保留原生失败能力；函数被测试框架执行不等于断言实际生效。

本地 canonical 与 PR 使用的基线不同，先核实际 request 的 base／candidate 和 PR 的目标、合并候选；分别保留输入差异与真实失败。目标分支前移本身不要求追平或重跑全部检查，只有实际冲突和明确依赖变化触发补验，不能把本地结果赋给另一棵远端树。

临时检出或等待通道缺失时，先核原任务、固定提交和保留引用；保护尚未保全的工作，再从已有身份恢复。目录缺失的原因保持未知，不能据此重新发布同一版本、重置分支或覆盖旧失败。

更新 Release 采用说明后，回读核对指定正文、标签、公开状态及资产身份与内容字段。下载计数是可变观察，不参与资产身份比较；仅计数变化时核原 before／after，不重复编辑已成功的说明。缺失资产、身份或内容差异仍失败，判法见负责迭代文档。

每轮用 PR／Release 引用原运行、版本、下游提交和未解决事项，复用原件的有限保留政策。原生等待通道丢失时保留句柄；长时间 `gh run watch` 的认证失败或网络读取超时不等于发布失败，用现有权限读取同一 run 并接续只读等待，不重新派发发布。用户取消或必要输入不可取得时停止依赖它的外部操作，交接精确恢复条件。不要为了持续而生成没有净改动或没有使用方的新版本。

收尾按各宿主已采用的生命周期执行。未采用 `automatic_cleanup` 时使用现有显式 cleanup 计划，不套用产品宿主的 `finish`，也不临时启用清理政策。核精确目标、保留引用、活跃使用方与失败原件的保留条件，再处置合格产物；入口拒绝不算清理完成。

把真实执行暴露的非显然问题修进本 skill 或其唯一负责文档；保留宿主特定边界，删除已被当前入口取代的提示。校验 skill 格式，执行变更所需的已登记检查，再用真实发布与下游结果检验指导是否有效。仓库中的此文件由登记源生成；更新个人目录的安装副本时同步已验收的生成结果，不维护另一套流程。
