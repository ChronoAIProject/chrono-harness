# 原始报告与文件保留

原件保留模块负责最终原件、固定报告位置，以及实际读取、上传和修复这些文件的消费者。这里的“消费者”指仍需要原文件的程序或活动；只要还有消费者，原件就不能清理。

该模块使用生命周期共用的内核 `ownership::Lease` 锁、逐项持久声明和 `artifact_disposal` 删除实现。测试样本仍由 worktree 的保留生产者负责，包括预先分配、复制成员、真实 CI 输出和诊断消费者。仅观察到历史路径，不会自动把它纳入管理。

**源码与本仓政策曾同步修改：**本仓选择 `chrono-output-retention/v2`。512 个输出的上限约束实际有关联的一组，不限制无关发布的全库数量或总字节数。其余限制为：每项声明保留 128 条摘要；每轮维护最多 256 步、25 ms、64 MiB 验证／元数据；每个输出最多 1 GiB、16384 个后代身份。移除后的元数据有 86400 秒诊断保留期，且只有保留根、引用边和使用凭据全部消失后才能回收。切换负责人时必须保留原结果、到期时间和活跃消费者。实现、迁移、真实 CI 和总存储成本在实际检查前均未测。

本仓检查使用当前检出的 `.chrono-harness/cache/bootstrap-owner-tooling/cargo`，由 bootstrap 和缓存生命周期共同管理。工具链选择及输入绑定由[输入说明](inputs.md)负责；完整输入闭包和跨环境同判仍未建立，实际路径、工具身份及原进程结果归本轮 state／线上原件。

发布工具及专属测试的编译目录、发布构建、公开和两平台安装目录，均按
projects.json 中的实际输出地址登记到 cleanup.json，采用 `finish-dispose`。
普通操作及维护在检出继续复用时保留这些缓存，明确 finish 或实际检出处置时才整目录回收，
并继续排除活跃使用方。已有工作树须通过正式 migrate 采用自己已提交的新政策；
只修改协调者政策不会追溯授权清理旧工作树。

## 对象观察的保管

PR 所有者复用逐对象消费者记录预约实际查询。序号、当前观察和成员集合在同一记录内原子更新；成员是当前 OPEN 观察及仍待结查询的真实操作输出，不另建待办总表。每次最终回读单独预约，完成命令只接受自身最后一个有效观察；旧查询晚返回时不覆盖较新的事实。输入交接及结果封存完成后才结清，未返回或发布失败仍保护。保留模块核输出身份、封存、代际和序号；PR 所有者负责实际对象语义和命令终结。空记录沿已有元数据期限回收，普通消费者不能直接改写对象观察成员。完整平台、宿主及未知任务恢复仍需分别验收。

它们的原生产者身份，供现有引用和有限期限内的回收使用；新实现统一通过
`lifecycle-original` 发布。原件及其必要引用释放前，不能靠移除声明丢失保管状态。
`cleanup.json` 的 `cache_history` 对每个地址的缓存尝试历史采用一天、64 项和
4 MiB 索引上限。程序只轮换已核验清理成功、记录了实际完成时间的旧代际，
保留当前代际、活跃使用、原件缺失或变化、未知完成时间和失败恢复。
保留义务使上限无法满足时报告 `over_limit`，不按年龄倒填成功或宣称已释放空间。
历史未纳管的辅助文件保持原有归属，修改政策不会扫描接管它们。

检查状态、当前指针或上传元数据，都不能单独证明外部消费者已经释放原件。必需报告保留根保护明确依赖的全部内容；只有历史引用或环，不会自动成为保留根。更新当前报告位置时，旧、新原件都保护到指针实际写入成功。未知或未发布的结果不能算成功。

进程输出保留沿用已有原始输出流／启动接口，未采用的宿主保持原行为。采用后，写入前先预留输出；进程启动失败也保留已登记的空／部分原件及修复状态，不能静默删除负责人的证据。进程模块仍须实际等待或排除后代，不能用 PID 或年龄猜测来替代使用凭据。

生命周期结果元数据记录操作、状态、精确报告摘要，以及失败时的 `/error` 指针。完整原件保留整条错误链，有限清单不重复复制大段诊断，原结果也不改变。

真实 bootstrap 样本重进缓存尝试时，读取全部原始输出流，并核验实际结束结果与独占删除回执。失败生产者若已结束、缓存已核验删除，可用新尝试位置重试，旧失败原件仍在原位受保护。旧规则即使已验证缓存删除也要求前次成功，现已修正。活跃／中断命令、缺失或变化的原件、矛盾结果、准备或释放失败仍会被拒绝；只允许一个未解决位置的限制不变。这只改变缓存进入条件，不释放最终原件，也不改写旧结果。

## 删除范围重叠时怎么处理

测试样本保管和最终原件保留各自有不同的释放含义。当前样本恢复适配器点名已登记的嵌套 Git 仓库及操作路径，再为精确路径取得删除凭据，并持有到操作结束。进入管理的锁在实际 IO 前释放，只有重叠发布会被拒绝。任一重叠的受管原件都会阻止样本删除，直到最终原件模块将其移除。复制内容使用同样保护和共用的逐项取消链接实现。

这些关系来自明确登记，不扫描目录推断。普通发布不能静默接管已有样本文件：按地址复用旧内容时须核对字节并保留原所有权；历史纳管须有精确的原所有者证据和排除保护。两套机制的最终组合与存活协调仓库验收仍须另行完成。

样本分配元数据按实际生产者分开。不可变 `objects.json` 绑定物理目录及 `producer-records/` 命名空间，不存可变成员总表。普通分配只在自身目录的独占保护下打开自己的记录，不用全局登记锁或进程级解码清单。维护枚举明确声明，保留不可用／已改变成员，继续处理独立成员。分配元数据正在修改时直接保护该项，不排队等待。发布上限仍为 30 秒。

## 临时目录整体滚动

`cleanup.json` 中的临时生产者可明确选择 `rolling_directory`，由
`TemporaryHost::registered_allocate` 在新分配时取得整个测试目录的所有权。
源码副本、fixture Git、安装副本、缓存和原始捕获共用目录寿命；不用逐文件登记，
复制输入也不再额外积累一套共享 `body-inputs`。
这项所有权只覆盖实际新建的测试分配，不接管普通工作树或历史未知目录。

本宿主对 worktree、CI、projects 和 workflow-tools 的临时目录采用以下有限窗口：

| 状态 | 何时起算 | 保留秒数 |
| --- | --- | ---: |
| 调用方正常交接且没有诊断用途 | `finish(false)` 的实际交接时间 | 0 |
| 调用方失败或明确请求诊断 | 实际交接时间 | 86400 |
| 中断，尚未交接 | 程序记录的分配时间 | 86400 |
| 已核验删除后的分配元数据 | 实际删除时间 | 3600 |

`finish` 只交接该分配的调用方使用责任，不声明测试、后台进程或工作树任务成功。
仍在运行的子进程和读取者持有同一个内核租约；取得独占保护之前，任何到期窗口都不允许删除。
显式实际消费者尚未释放时也继续保护。`retain_diagnostic` 选择有限诊断窗口，
不再为普通测试现场建立一个永不自动释放的复核引用。

普通交接仅尝试回收当前目录；中断和到期对象由现有 `chrono-worktree maintain` 恢复。
删除立即重验政策、目录 inode、出生声明、引用、内核凭据及宿主已提交／索引源码。
目录内的外部符号链接只移除链接。清理失败保留原错误并使维护失败，继续独立对象。
目录已缺失后，只凭绑定的删除意图恢复，不能据缺失猜测成功。

分配的意图、租约和回执统一放在分配之外的单个元数据目录。
到期后，先原子交接原登记，再把元数据目录交给专用删除目录整体回收；
现有维护恢复两处交接之间的中断和已经开始的物理删除。
专用删除目录只保留一个绑定物理身份的常量所有者声明，不积累逐文件清单或永久墓碑。
保留窗口不能改写原结果，清理回执也有自己的现役报告使用方及保留政策。

产品与宿主政策同时变更：上述四个实际测试发布者同步迁移到新分配／交接接口，
诊断与中断寿命由宿主选择；目录删除判定和窗口选择由同源 Verus 实现负责。
IO、原子重命名、内核租约和恢复组合仍须行为验证，局部证明不证明整套事务。
正式检查继续执行原完整 core／adoption，包含目录回收的行为回归。
实现、构建、维护、CI 与存储的总成本以实际候选结果为准。

临时生产者还可用 `operations` 选择实际登记操作。普通 `use` 为该操作新建一个
整体目录，以 `CHRONO_ARTIFACT_DIRECTORY` 和 `TMPDIR` 交给实际子进程；等待原进程
后按真实退出结果交接，后代持有的能力继续排除删除。操作只能属于一个生产者。
源码、固定报告和原始退出结果仍归原负责方，目录回收不把失败改成成功。

本仓 bootstrap 测试通过同一 `use` 入口运行，整个运行目录负责其 custody 样本、
临时安装与命令捕获。成功运行结束后尝试整体回收，失败／中断仍选一天窗口。
历史 `bootstrap-custody-tests` 等旧目录不由新分配路径接管，须先完成原消费者交接。
这次同时修改生命周期产品、测试入口和宿主政策；新增运行范围的实际验证仍为必需。

本宿主还为标准检查 `validate.delta` 和源码安装 `bootstrap.build` 选择同一
整体滚动入口。由入口转交的 `TMPDIR` 中的临时目录、失败现场和命令捕获，

实际所有者管理；固定报告、当前安装和已有缓存不因运行目录回收而解除保护。
这项宿主采用复用现有能力，不增加按文件登记、后台服务或另一套清理入口。

旧的汇总式样本存储须通过 `chrono-worktree migrate --path COORDINATOR --partition-producer ID` 明确转换，普通操作不回退读取旧格式。转换保留源字节、精确结果和活跃使用凭据，把暂存记录绑定到源摘要、长度和物理身份，拒绝已变化的暂存字节。新命名空间启用前中断，只能用同一精确输入继续。

## 每个输出和消费者各自登记

`output-retention-v1/objects/OUTPUT_ID/record.json` 负责一个输出、原结果、入向关联、精确消费者名称和有限移除摘要。`roles/SHA256(ROLE)/record.json` 负责一个消费者的成员关系。命名空间没有可变成员总表、全局进入锁或汇总清单。普通发布、读取、完成、释放只访问明确地址及向外依赖的内容，不触发全库维护。唯一输出 ID 也不需要共享计数器。

路径声明按路径段组织成树：祖先持共享锁，目标持独占锁。因此兄弟路径可同时发布，目录树操作则排除声明的后代。原件写入者和固定报告位置继续持有绑定身份的内核使用凭据；创建和移除元数据只锁对应目录，不加全局事务数量门。获取锁仍限五秒，超时不使别人的活跃保护失效。

更新关系时，先持久保存保守的入向／消费者关联，再发布来源声明，最后移除被替代关联。中断会多留保护，等负责人恢复时协调。内容 IO 期间保留原件凭据，但释放元数据独占锁。完成时重新读取当前记录，保留 IO 期间新增的引用。读取范围只通过已有描述符交接，转交明确取得或发布的原件。

显式 `maintain` 在节点、字节、元数据和时间预算内枚举声明。它逐个尝试实际关联组，不等待繁忙元数据；失败时保留原件、记录错误，继续独立组。报告注明已访问范围，遍历不全或被拒时写 `remaining_outputs:null`，不能编造全库剩余零项。

维护沿原件的出向和入向引用确定关联组。共享同一消费者不会把其余独立成员并入该组；维护在消费者声明的独占保护下核对本组成员，保存时保留未访问的成员及中断时留下的保守关联。因此，同一保留根下的无关记录繁忙或损坏，不阻止一个已释放旧报告的回收；当前成员及其引用仍受保护，25 ms 等原预算不变。

已封存、没有入向引用和保留根的旧报告，可以作为单独的退役目标。维护仍排除它的直接原件；直接原件已封存且没有待退役凭据时，当轮保留这些原件，只移除目标报告的入向关联，不读取共用原件的其他报告或继续展开原件的向外依赖。直接原件尚未完成时，恢复完整关联组处理；原有环和中断交接保护继续适用。已封存的当前保留根也无需读取其余报告来证明自身仍须保留。所有分支继续受原关联数量上限约束。

有关系未访问时，范围仍为不完整，`remaining_outputs` 写 `null`。同轮多个退役目标共用原件时，剩余数量、字节和待退役凭据按输出身份只计一次；实际 IO、节点和删除效果仍累计本轮原结果。没有扩大预算，也不据此宣称全部历史产物已回收。

装载时，只有已排除且当轮明确保留的原件可以保留未访问的向外依赖；可变更、可退役的输出仍要求依赖全部进入受保护的关联组。当前保留根即使位于环中也沿用这个边界，范围与计量不能因省略读取而宣称完整。多目标回收可以在原预算内分轮继续，验收仍核最终实际删除、唯一计量和原件保留。

非阻塞维护在读取每份关联声明前，先尝试取得并持有该声明的原元数据独占租约，再沿其显式关系继续发现。全部路径排除取得后，直接使用这些受保护的读数，避免完整重读同一关联组。遇到繁忙的元数据或路径立即保留该组并释放已取得的租约；不会反向等待持有路径的普通发布者。普通等待型操作仍按路径、消费者、原件的原顺序取得排除，并在排除下重读核对。所有读取继续计入原元数据容量，节点、字节和时间预算不变。

路径声明的初始化检查只观察是否缺失；已有声明在取得原路径租约后读取并验证地址，避免在锁外先完整读取一次。缺失声明仍在独占租约内重新检查并初始化，文件类型、符号链接及物理身份检查继续适用。

声明读取按已打开普通文件的实际长度预留有界缓冲区，避免空缓冲区反复扩容和小块读取；读取时仍限制最多 8 MiB 加一个越界检测字节，读取过程中增长也不能越过原上限。Unix 打开声明时不跟随符号链接，且不会阻塞等待 FIFO，随后核对普通文件类型。已有路径声明在原路径租约内执行这些检查，省去锁外重复的链接预检；缺失声明仍须在独占租约内重查后初始化。原元数据计量、关系保护和单轮预算不变。

非阻塞维护只读取实际关联对象的路径地址。祖先目录仍持有相同的共享租约，阻止重叠发布或目录删除；本次没有读取者的祖先地址文件保留原样，不因其内容损坏而阻止目标回收。目标地址仍须完整检查，普通发布仍读取祖先映射以核对重叠预约。关联声明沿已经核对并取得排除的目录地址读取，构造维护结果时复用仍持有租约的读数，不再重复解析同一物理目录。全部实际删除仍核对原身份、源文件排除及使用方保护，25 ms 等预算不变。

关联组的维护游标只保存到读取时使用的第一份可退役地址声明，跳过当轮明确保留的原件。分步删除旧报告时，不把同一游标重复写入其余未变化的依赖声明；实际结果、引用和删除进度仍由各原件自己的声明保存。后续维护继续读取同一负责声明，关联组变化后沿现有取模规则选择下一项。节点、字节和时间预算不变。

bootstrap 的恢复原件回归分别核对消费者释放和后续维护：释放回执只结束精确消费者的保护，不承诺删除。维护若因该原件的元数据繁忙而拒绝，测试要求错误与保护项都精确指向它、范围不完整、剩余数量未知、未删除且原件仍在；其他错误继续失败。没有增加重试或预算，也不把释放当作工程完成。

事务维护只枚举现有的 `transaction-gates/` 地址，再读取各地址对应的事务声明。该目录在声明发布前创建、声明退役后移除；无需增加另一份索引。原件使用凭据仍在自己的地址，数量增加不再拖慢事务发现。512 项原件、25 ms 的原回归保留，不提高预算或引入总游标。

绑定身份的实际删除，以及精确源码／索引检查仍为必需。判断保留根消耗元数据和时间预算，不占实际删除步数，所以一个受保护的当前报告不能独占单步维护。只有已移除、无引用且无活跃凭据的元数据才能到期；路径树修剪逐对象有限推进。未知成员和身份被替换的对象继续保留。

现有回归覆盖：其他记录被锁或损坏时独立发布；原 420 输出／28 发布者／五秒用例；以及保留 512 份受保护原件时真实生命周期／bootstrap 发布。最后一种要求无关占用不阻止独立发布，同时保护活跃生产者／读取者、失败／中断原件、当前／交付保留根和依赖，且源码／索引字节不变。源码中有实现不代表测试通过或已经部署，仍须候选检查和宿主切换。

## 正式入口和操作要求

```sh
.chrono-harness/bin/chrono-harness retention --host-root H --request P
```

`P` 是相对根目录的精确 JSON 请求，最多 64 KiB。操作有 `maintain`、`migrate-policy`、`enroll`、`release`、`protect-consumer`、`release-consumer`、`acknowledge-delivery`。程序产生结果后退出 `0`；输入无效、身份改变、使用凭据不可取得或政策拒绝时退出 `2`。结果不宣称历史工程工作已经完成。

退役工作树时，调用方可用同一入口的 `release-preserved` 交接一份已保全的普通原件。请求逐项声明 `original`（id／path／identity）、完整当前 `roles`、独立物理 `survivor_root` 及其相对 `survivor_path`、`sha256`、`length`、`current_consumers_released:true` 和实际 `reason`。调用方先等待全部旧使用方，负责保留副本的用途、期限及旧路径映射。程序核原件独占使用凭据、完整角色集合、原件和副本的实际字节；副本必须位于退役宿主之外。只释放该原件在所声明角色中的成员，保留同角色的其他成员、原结果和到期时间。目录、活跃读写者、角色漂移、缺失或变化的副本均拒绝。后续仍由原 `maintain` 负责实际删除，再走 worktree 的正式清理入口；释放回执不表示删除或历史任务成功。中断重进须核同一副本及原回执。此路径复用现有逐对象租约及摘要，不增加总锁或历史兼容。真实宿主交接和整体成本在实际验收前未知。

调用方已持有实际剩余原件清单时，向同一 `maintain` 请求提供非空、无重复的 `originals:[OUTPUT_ID,...]`。程序只处理这些声明的依赖关联组，沿用原节点、字节和 25 ms 上限及活跃使用保护，不枚举无关输出、事务或消费者元数据。`scope.kind:declared-components` 的数量只描述所选范围；不宣称全库为零。这个参数用于避免诊断保留期内的旧记录反复耗尽本轮预算，不增加游标总账或普通入口前置维护。

这两项请求的清单边界、完整角色比较、单项成员移除和枚举范围选择直接使用同源 Verus 实现，证明作为专属测试的必需前置。文件 IO、租约和其余保留状态仍由现有所有者负责；证明范围与新增政策成本见 [Verus 实施说明](verus.md#原件交接与定向维护)。

发布先持久保存意图、精确目的路径和父目录身份，再建立空暂存文件，把其 inode 身份持久关联，最后通过内核“不覆盖已有目标”的重命名发布。实际完成时记录原结果。普通已采用入口可恢复有限统计、中断创建和部分操作。每组关联图、目录快照、摘要环和读写都有上限。关联组或输出过大时拒绝受控发布；无关原件不占进入配额。外部构建者被排除后仍须统计其结果。

每次实际操作都重新检查政策、精确输出／条目身份、引用、使用凭据，以及已提交／索引源码。封存清单和游标只覆盖明确纳管的输出。替换、内容变化、未知新增后代和特殊文件一律保留。符号链接只删除链接，不跟随目标。逻辑删除字节、实际观察的分配块和未知物理节省分别报告。维护摘要保留原结果，不声称移除后原字节还在。

调用方持有待迁移原件清单时，可向 `migrate-policy` 同样提供非空、无重复且不超过当前关联容量的 `originals:[OUTPUT_ID,...]`，并继续提供精确的 `previous_policy:{path,sha256}`。原有事务恢复与排除预检仍适用；输出迁移只检查所声明原件及其向外依赖。无关记录的其他旧绑定保持原样，不阻断这个集合。所选依赖中的未知绑定、缺失声明和活跃生产者／读取者仍拒绝迁移。省略清单时仍检查已登记全体。回执的数量只描述实际访问范围，`scope.complete:false` 不宣称全库已采用当前政策；原件字节、身份、结果、期限、引用和保留根保持不变。该范围选择复用现有显式清单校验、逐对象保护及两遍迁移，不增加锁、清理预算或后台维护。

政策迁移要求精确的旧政策字节，以及对原生产者／读取者的独占排除保护。它先逐项检查已登记输出及其向外依赖，再按相同范围重新取得保护、重验并只更新政策摘要；不同时持有无关对象的文件句柄。反向引用和保留根不扩入迁移范围，也不改写其记录。路径、原结果、到期时间和部分操作保持原样。必需依赖缺失、统计不完整、容量不兼容或仍有活跃消费者时拒绝该依赖集合的迁移。预检失败不切换绑定；写入阶段中断或状态变化时，已经切换的记录保留当前绑定，同一精确请求可重新进入。不支持倒填时间、扫描接管、手工改清单或抬高容量。

遇到未附着或退休中断的事务，迁移入口复用现有逐地址恢复：取得原地址排除和适用的能力租约后，回收该事务的声明与能力，再继续核对输出。声明已移除、只剩已登记空地址时，同一恢复所有者确认排除后收尾。仍有活跃持有者、无声明的能力或未知成员时保留并报错；未知地址不被认作自有事务。原件、结果、期限和引用继续沿原迁移合同保护。

独立发布或迁移中断后，旧绑定与当前绑定可能并存。正式迁移接受请求所给的旧摘要及当前摘要，拒绝第三种未知绑定；仍在写入前核对当前政策范围，并排除全部实际生产者和读取者，包括当前绑定下的读取者。普通读写仍只接受当前绑定。回归覆盖混合绑定、未知旧摘要、活跃读取者、原字节／结果／期限／保留根不变，以及同一请求重复进入；没有新增全库读写前置或预算，总迁移成本未测。

修复消费者的声明放在待清理原件之外，并绑定摘要：

```json
{"schema":"chrono-retention-consumer/v1","consumer":"ACTIVITY_ID","purpose":"实际复核所需输入与释放责任","originals":[{"id":"OUTPUT_ID","path":"EXACT_PATH","identity":"EXACT_DEVICE:INODE:TYPE"}]}
```

`protect-consumer` 接收 `declaration:{path,sha256}`。`release-consumer` 另需 `receipt:{path,sha256}` 和 JSON `pointer`。负责消费者实际核清输入、将仍必需原件交给真实消费者保护后，在指针处发布 `{consumer, declaration_sha256, state:"released"}`。

释放时核对精确成员、身份和读取者独占排除，不改变到期时间或原结果。声明不完整／缩小、状态未解决、原件变化或仍有活跃读取者都会被拒绝。保留期内，有上限的摘要／数量回执支持同一精确请求重进；新消费活动使用新 ID。

历史纳管另需政策选定的精确生产源码／回执、原所有者租约、路径／结果绑定、必需保留根，以及适用的精确消费者释放证据。它不扫描也不删除。兼容部署必须等待或排除旧写入者和读取者，包括不支持这些凭据的旧实现。未完成切换前，不能混用旧严格清单或二进制。

## 迁移和部署

完整报告同时保留原检查失败和发布错误。报告位置的租约持有到指针实际发布和结算完成；发布失败时保留修复使用方和当前保留根，不确认释放。

旧布局切换前，保管者须排除原生产者和实际读取者，保留精确清单、政策原件与领域状态，再由兼容所有者采用已提交政策。暂存、所有者部署和普通 bootstrap／检查统一遵循[工作树生命周期入口](worktree.md#kernel-ownership-and-unfinished-cache-recovery-v2)。中间候选只作暂存证据；普通操作不解码旧汇总布局。
