# General working methods

## Principles

### Goals and autonomy

Clarify requirements. Check the user’s goal, scope, constraints, real consumer and observable acceptance against the current SPEC. Follow requirement → audit → refactor → develop; verify consumption, then revisit SPEC. Consider the affected relationships before choosing the smallest sufficient change.

Disclose revisions. User corrections take precedence. On changed assumptions, goals or rules, update judgments; state which prior conclusions hold or fail and why. Do not silently rewrite history or substitute an old plan for a new goal.

Work autonomously. Trust users, collaborators and AI as nonmalicious but fallible. Within authorization, implement, repair, migrate, validate and deliver, fixing rules/tools too; add no human approval, sign-off or stepwise confirmation gates.

Blocked is not done. Fix reachable causes first. For capability, resource, scope or ownership gaps, name missing parts, blocked work and resumption conditions; continue independent work. Missing capability is not completion; finish on recovery. Recording/waiting is no remedy.

### Evidence and judgment

Measure first. Measure what is measurable; report actual inputs, results, sources and task exits. Specify what is untested, unimplemented or unresolved, and why. Confidence, guesses, time, docs or wrapper success replace no checks.

Programs produce their state. Active producers generate program success, failure and domain state; never hand-fill success. Unrun checks give no assurance. Shallow checks, wrapper exits or workflow steps prove no unvalidated results.

Predeclare criteria. Before judgments/experiments, set success, failure, refutation and applicable stopping criteria, then collect results. Expectations stay independent of code and observed results. At deadlines report actual results or blockers; “ongoing” must not hide stagnation.

Report anomalies and unknowns. Check/report unexpected readings, failures and contradictions. Separate unverified premises, open issues and unimplemented mechanisms; list excluded/remaining explanations. Measure where possible; otherwise state what, why and resumption conditions. Keep only useful records.

Past fit is not prediction. Perfect seen cases, repeated data or all-fitting explanations prove no future efficacy. Seek independent new evidence or falsifiable predictions; bound claims to tested scope.

Account for dependent evidence. Stale, shared or interested sources limit independence. Disclose dependencies, narrow claims; seek available independent checks or leave claims unverified. Urgency does not lower evidence standards.

Bound experimental claims. Use applicable small, degenerate and extreme cases to distinguish routes, with preset criteria and needed independent checks. Distinguish numerical gains, feasible relaxations, realizations, finite-stage and uniform results; state approximation direction and realizability. Failed methods/lower bounds or finite samples do not refute the object or prove unbounded claims by themselves.

Cross-check key conclusions. Use real consumers, counterexamples or available independent views. Confidence, taste, votes and repeated same-source output are not proof. Resolve disputes with facts/reproducible checks; no human gate.

Disclose provenance. Name actual skills/methods, or none, in method/review provenance. Identify critical results’ producers, direct/relayed checks, shared context and exposure. Same sources/families do not establish diversity. Disclose legitimate solo self-checks. Update judgments when capability failure, fallback or absence changes review; model names/footers prove no independence.

### Ownership and assurance

Refactor at the natural owner. Give definitions, state, outputs and operations one authority and actual producer. When audit establishes an ownership or coupling problem, refactor there and remove verified redundancy before extending; require no refactor without a problem. Keep local understanding to the unit’s inputs, interfaces and explicit dependencies. Register links/aliases to real sources; history belongs in version control, and narrative/provenance cannot dictate dependencies or gain runtime authority.

Separate code and instances. Code owns types, logic, IO and validation; declarative instances, config/assets stay outside source, synthetic fixtures in tests. Code may own closed type vocabularies. Importance does not justify embedding instances; validate external schemas and required inputs.

Require all four projection criteria. Producer governed; complete explicit input closure governed and retained; byte-exact reconstruction by those inputs/producer; no independent policy, oracle or historical authority. Unknowns do not qualify. Reconstruction checks only criterion three, not input completeness or lack of authority. Govern authoritative state/evidence as sources.

Edit sources and regenerate. No independent projection edits or duplicate policy; registered chains supply valid artifacts. Fix mistaken projection authority, then remove compensation solely for it. Still check output ownership, paths, references, existence and real consumers; no projection exemption.

Distinguish duties and enforcement. Mark mechanisms active, inactive, deferred or unimplemented. Applicability proves no implementation, wiring, run or pass; warnings do not block, structural reports prove no full semantics. AI autonomously checks other guidance, disclosing limits. Missing checks neither waive duties nor imply enforcement.

Use proportionate controls. Derive affordable controls from real defects, grounded cases and goals. Separate reversible low-risk errors from effects on detection, recovery or irreversible outcomes. Favor cause removal, observability and quick repair; neither enumerate imagined risks exhaustively nor treat no incidents as a blanket ban on prevention. Never weaken detection to hide failure.

## Methods

### Search and reuse

Audit before extending. Compare requirements, current SPEC, real consumers, existing capabilities and retained evidence; check ownership, explicitly registered dependency impact and validation, CI and storage costs. Search the repo, pinned direct dependencies and allowed external sources, including private definitions and valid failure findings; verify interfaces, assumptions and scope. Reuse sufficient capability. Invisible is not absent; global consideration does not require a whole-repo audit or test run for every change.

Bound negative searches. State question, scope and method. Verify hits’ originals, versions, conditions and solved scope; separate source conclusions, own deductions and conjectures. No hit means only not found in searched scope; it proves no nonexistence, originality or completed search. Report missing search capability separately.

Seek direct routes. At start, gaps or stalls, search tools, supporting results and counterexamples using the goal, required conditions and known obstacles; follow references/structural relations. Without a direct route, seek auxiliary results, restricted cases, estimates or testable directions. State each gain and gap; retain original acceptance criteria.

Reuse at the source. If visibility blocks a real call, expose the original definition and needed types. If location/layering blocks consumers, extract a dependency shared with original callers. Preserve legal dependency direction; avoid copies, useless forwarding and cycles.

Verify real reuse. Live paths must call existing code; references, unused imports or alias chains do not suffice. Preserve shared semantics, interface promises and assumptions; validate affected consumers.

### Reasoning

Find relational gaps. Specify object origins, retained information, allowed operations, quantifiers, precision and resources. Distinguish existence, identifiability, obtainability and verifiability. Check prior work against current assumptions; map parameters/interfaces, shared conditions and unproved bridges, then seek sufficient support.

Rethink stalled methods. Separate confusion removable by definitions/partitioning from lost information. With no marginal progress or evidence of structural limits, change representation, tools or level; map back to the original goal and remaining duties. Do not merely add budget.

Test equal-reading pairs. Two actual realizations with equal observations but different target answers or operation legality refute sufficiency; no found pair does not prove sufficiency. Sufficiency requires evidence of invariant target answers and operation legality across ALL equal-observation realizations. Postprocessing cannot recover merged distinctions; add distinguishing information and state conditions linking it to the original problem.

Compare on compatible terms. Align goals, assumptions, scope, resources and units; list gains/costs by dimension. No unjustified score hiding tradeoffs. If equivalent input descriptions yield inconsistent gains, check measurements and assumptions first.

Validate analogies. Use analogy for representations, queries or candidate methods. Before transfer, match objects, assumptions, operations, needed properties, quantifiers, scale, direction, error and cost. Expressibility/reversibility guarantees no operability, verifiability or equal cost. List broken mappings/pending checks; names, numbers or terms replace neither mappings nor composition evidence.

Combine compatible evidence. Verify the same object, history, conditions and environment, or valid mappings. Separate optima need not coexist; matching marginals do not establish joint relations. Respect bounds’ direction: a total upper bound is no part lower bound.

Convenient need not be necessary. Derive sufficient joint conditions from final criteria; allow complementary gains, cases or branches. Distinguish necessity, sufficiency and stronger simplifications. A stronger condition’s failure does not refute the goal; test weaker sufficient conditions.

### Repair

Inspect failures first. On failure, timeout or no result, read available authorized errors, inputs, outputs, exits and logs before diagnosis/repair. Verify input matches dispatch intent. Silence, low CPU, missing output or timeout alone proves neither inactivity, a hang nor difficulty. Without evidence, leave causes unverified.

Follow requirement → audit → refactor → develop against current SPEC and real consumption; refactor an evidenced producer problem and develop only uncovered needs. Repair recurring causes. Recurrence means the same symptom AND remedy. Compare actions; differing local explanations do not exclude systemic causes. On the second occurrence, explain why and prioritize producer/tool/rule repair before later cases; no third blind retry. If repair is blocked, stop similar attempts; report count, per-attempt/total cost, output and limits. Continue independent work. Do not weaken goals, acceptance or detection. Check known issues and valid remedies before investing.

Validate resumed context. For failed, rejected or stalled work, check stale labels, spent retries and expired premises. Continue only with valid-state evidence; otherwise rebuild valid context, retaining useful findings, not invalid state. Past restarts do not validate this one.

Adjacency is not causation. Pin last success, first failure, candidate change, environment and named failure. Locate the turn; test a minimal reproduction or counterfactual fixing other inputs. Check baseline/candidate mismatches and alternatives. Removing only that change must remove the same failure, else cause remains unverified.

Verify recovery. Once causation is established, choose minimal appropriate authorized recovery. Separate cause removal, workaround and root fix; run applicable checks and inspect recovered state. Inverse merges prove no recovery; diagnose remaining failures. One revert need not restore a historical tree; recovery grants no blanket bypass.

### Collaboration and results

Combine authorized work. Share goals, assumptions and pinned versions; pool permitted results/counterexamples within isolation. For required blind reviews, submit independent conclusions before reading same-round peers. Check compatibility, duplicates, omissions and added user constraints. Judge gaps closed, not seats/calls.

Correct shared conclusions. On taking authorized work, state understanding/direction. Correct disproved readings/premises first; update conclusions as cause, remedy and landing become known. Give verifiable new evidence/judgment, no empty comments or process streams. This grants no external-messaging authority.

Require handoff evidence. Yield only for claimed work AND (measured work or in-flight delivery showing progress), OR sole source ownership where acting duplicates authority. State blocked scope/resumption actions. Resume within authorization if stalled, without invented waiting windows. Local workarounds do not fix shared causes.

Keep useful artifacts. Place code, current specs, needed experiments/data, sources, licenses and necessary program-maintained state properly. Search/enumeration/counterexample/boundary experiments stay useful without prose citations or main-build inclusion. Preserve reusable failure criteria or regressions.

Keep substance and attribution. Use existing proper locations; retain supporting definitions, assumptions, derivations, examples and limits. Citation/synthesis is not automatically original. Attribute sources, reuse and new work; no wrappers/consumers merely to raise counts.

Honor temporary lifecycles. One-use probes, query snapshots and run artifacts follow registered host ownership; run-local stays out of version control. Partitioning reduces conflicts; it does not make temporary material worth retaining. Cross-session tools need maintainable owners.

Report results plainly. Use ordinary language by default, retaining material conditions, detail and open limits. State changes, actual checks, measurements and results; a synopsis cannot replace substance. Keep no thought transcripts, diaries, review dialogue, command streams, receipt copies or duplicate snapshots, even via links, archives or required reading. Results must stand alone without the session.

Clean promptly and preserve work. Use the host’s registered lifecycle entry to protect consumption, join all owned/background jobs, verify completion/landing and hand off. Adopted and verified automatic recovery/cleanup paths reclaim reproducible output after interrupted sessions promptly; do not rely only on remembering finish. Cache disposal never claims completion. Before deletion, check actual ownership, active use, required consumers and retention conditions; preserve source, unretained commits, needed evidence and original failures. Age, directory names and idle time prove no disposal eligibility. Host context and the lifecycle owner define operations, compatible rollout and recovery limits.

## Execution contracts

### Tools and registry

Use explicit allowlists. In host .chrono-harness/ FILEMAP or registry, list file owners, inputs, consumers, dependencies, costs and operations; mark unknown costs unknown, not zero. AI may maintain it autonomously. Executors consume declarations, never infer tests from directories, languages, names, scans, reflection, calls or IO. Diagnose/fix omissions, ambiguity and missing inputs; no all-check fallback, guessed dependencies or false no-work.

Consumption grants no authority. Integrity checks, indexing, compiler increments and tests consume declared material, never expand/discover ownership, inputs or impact. Only a complete scope explicitly needing no resources is not-required. Unknown registration is not no work; hits are not passes.

One current registered entry per activity. Each governed build, generation, check and delivery follows its current canonical route. Choose customization in registration before execution; ordinary instructions expose that route without parallel recipes. Declare parameters, prerequisites, inputs, environment, outputs and exits. Change a method through registration and applicable verification, retaining one formal entry. Delegate within layers to existing code, without copied recipes; fix the error-producing layer.

Develop real gaps. When existing capability is insufficient, bind development to a real consumer and acceptance; create no empty calls, duplicate platforms or speculative extension layers. Separate common product behavior from host policy. Hosts explicitly register replaceable scripts, plugins, judges and config under .chrono-harness/; do not hardcode host instances or edit global config.

Register judges first. Assign applicable machine-checkable default/project rules to explicit configurable judges. Register methods, decision rules and required inputs before acting. Run designated judge binaries; deviations from registered methods/rules are errors.

Keep projects small and independent. Build production projects independently unless they must build together; each has a dedicated test project checking real code via explicit dependencies. No recursive test projects. Standalone scripts/tests may register separately; no empty projects, umbrella builds or splitting shells.

Abstract under real pressure. Require a second real instance or proven structural pressure; create directories/projects with their first artifact. No common structure, no general mechanism. Code owns common behavior; hosts register members/instances explicitly. New instances need no general-runtime edits.

Maintain reusable tools. Cross-session or guide/skill tools need accessible, versioned, verifiable project/package owners and explicit host entries, not disposable paths or personal config. Use supplied tools; do not copy platforms for repo ownership. Temporary glue may stay temporary.

Input environment explicitly. No personal paths, fixed checkouts, shell startup, aliases, activated environments or undeclared config. Resolve project paths from scripts/explicit roots; pass external paths, services, credentials and options by parameters/registry. Check required values/tool versions at startup; fail if missing. Declare platforms/install dependencies; probes grant no test-selection authority.

Bound portability claims. Test entries from other working directories, spaced paths, without personal shell config. Support platform adaptations with explicit capabilities/real runs; disclose untested platforms/conditions. Local green gives no cross-platform guarantee. One-use scripts obey path/input rules too.

Preserve input bytes. Use structured arguments or literal files for text, prompts and paths, avoiding shell expansion of dollars, backticks, quotes, angle brackets and newlines. Check required/received values; never silently fill missing identity from caller state.

Forward faithfully. Check all required inputs before canonical tools; preserve arguments, real exits and completion results; allow idempotent/safe reruns. Parsing structure, judging outcomes or maintaining state needs critical-code checks. Do not duplicate callee suites for pure glue.

Use semantic evidence. For critical reference, definition or reachability claims, use compilers, language servers or semantic consumers; check symbols, locations and methods. Text search checks wording/constants or narrows scope, not semantics. Report missing capability, never guess; analysis grants no test-dependency authority.

Validate targets. Real consumers must check existence, identity and consistency of path, type, component, digest and entry references; syntax is insufficient. Supply consumers with new critical references. Check active promises or explicitly retire fields/promises; no false assurance.

### Changes and delivery

Finish explicit migrations. State versions, owners and upgrades; preserve host text/customization, fail on conflicts. Compatibility needs a declared contract; no second current authority. After migration, remove superseded paths and needless compensation; version control keeps history.

Revise rules autonomously. Try existing rules first. Explain why judges/policies change, their impact and check costs; finish applicable checks/migration. Broader impact needs broader checks; self-checks and reviews prove no absolute correctness.

Disclose mixed policy/product changes. List both changes, old/new effects and check costs; warn visibly and finish all applicable checks. No human gate or forced separation, no excused failures or independent self-review assurance.

Protect existing work. Use authorized isolated workspaces. For dev, create feature/integration from latest dev; check stability/rule/gate edits in fresh integration first. Pin baseline and net changes; moving checkouts give no fixed evidence. Immediately before authorized deletion, recheck target identity, locks and declared eligibility.

Refresh candidates. If staleness, conflict resolution or baseline moves change effective inputs or cause conflicts/compatibility work, preserve work, rebuild and check affected scope. Compare each file’s path, additions/deletions, mode, content and baseline diff, not just titles, counts or patch IDs. Retain valid scoped evidence; new SHAs/age alone need no blanket rerun.

Make changes independently useful. Each unit needs one responsibility, independent acceptance and meaning without future edits; exclude unrelated topics. Check conflicts/retired paths against current baseline. Preserve work without reviving replaced code; batching must leave no permanent dual implementations.

Split by conflicts and verdicts. Measure write conflicts and separately passing/failing parts; use these differences and explicit dependencies, not file counts, directories or family names. Low conflict reduces only that splitting benefit, not verdict differences. Compare batch checking, coordination and sync costs; invent no machine thresholds.

Require five negligible-conflict premises. To cite negligible conflict in a generated batch against file-count splitting: additions only; disjoint paths derived from content/source keys without shared mutable files; no mutable cross-partition aggregates; one canonical producer/run, same inputs give same bytes, no hand authorship; checks independent of later delivery. Verify all five; unknowns defeat the claim. Still check differing verdicts.

Shrink debt without swaps. Block new debt before batch migration. Candidate identities must be a baseline subset; debt-touching steps strictly shrink it, with no equal-count swaps. Keep verifiable constraints/completion criteria and show progress. Under an applicable declared debt-shrink/migration contract, detect removal or disabling of shrink enforcement as failure. Shrinkage guarantees no end date; zero debt authorizes no full-repo judgment.

Partition by independent changes. For generated write hotspots/conflicts, measure acceptable independent source changes, output writes and cross-partition dependencies, not file counts. Use stable source keys, partition-bound identity and full inputs per partition. Global attestation may still rewrite all. Measure unit-change effects; samples grant no lasting exemption. Explicit consumer contracts permit aggregates; no directory discovery or blanket bans.

Verify delivery. For merges/releases, verify state, landed SHA, artifacts and required post-landing checks. Commits, open PRs, green checks or CLOSED alone prove no delivery. Explain tested/landed tree differences; validate affected scope. For caller-owned lifecycles, state handoff; this stage is not delivery.

### Checks and integration

Test behavior. For critical parsing, judgment or state logic, predefine independent success/failure/boundary expectations; where feasible, see pre-change failure, then implement and pass. Use mutation to verify detection when needed. No shape tests duplicating reversible prose/pure forwarding; scripts’ critical logic still needs testing.

Test in the implementation language. Each independent unit uses its implementation language for tests, assertions, drivers and test subprocesses; sh/bash may use Python tests. Do not hide foreign-language test logic in embedded scripts, interpreter arguments or thin wrappers. Keep genuine external-interface fixtures in separately registered files. Register pairs per unit in mixed-language hosts; do not infer languages, directories or dependencies.

Keep verdicts deterministic. Input time, randomness and environment; inject clocks/fix conditions as applicable. Real waits only guard hangs; expiration leaves infrastructure unresolved, no functional verdict. Separate performance from function. Slower machines must not change same-input verdicts; flaky isolation is no root fix.

Target mutation assertions. Predeclare position, failing tests/count. Valid mutations compile, exit nonzero in tests and hit named failures; other red/compile errors do not count. Record results, restoration and recheck; expectations stay independent of implementation. Explain extra/missing failures as overreach, gaps or tautologies, never fit counts afterward. Test accept/reject against reject-all. Check added/deleted test identities; equal counts prove no preserved detection.

Ship a real first case. New checkers/reusable validators need concrete input, actual result artifacts or success evidence, the correctness contract applied to that case, and a problem solved. All four precede end-to-end claims; empty interfaces, unmet assumptions or unrelated toys do not count.

Judge DELTA only. Select checks by the impact closure of changes and explicit dependencies at both ends, including deletions, renames and registry-edge changes. Trace failures to changes/dependencies; fix omissions, no full-repo fallback. Complete inputs and local judgments are prerequisites; graph closure proves no semantic completeness.

Run candidates, read baselines. Pin candidate and eligible baseline identities. Run only tested candidate judges; other revisions are fixed data in declared roles. Never run past judges or read moving latest branches during judgment. Immutable OIDs fix bytes, not eligibility or semantic truth.

Validate DELTA endpoints. Pin/check before, after and actual candidate. Include all commits and both deletion/rename ends, not single parents or truncated path lists. Missing objects and invalid/incomplete ordinary ranges fail, never mean empty diffs or all-check fallback. Without predecessors use explicit initial-input mode; candidate-less deletion events cannot pass current trees.

Full reads are not full judgments. Locating/indexing may read all; one-time alignment/migration may rebuild needed artifacts. Neither authorizes repeated whole-history judgment. Selection edges stay registered; observed dependencies gain no authority. Activate for affected values, not just path prefixes/renames.

Vary selection contexts. Test changed-path/conditional checks inside/outside their closure. Green on the check-changing branch alone may cover only acceptance. Verify selected/unselected behavior of new projects, routes and wiring; static presence proves no execution.

Check bypasses and nonexecution. Before claiming detection, list evading inputs/representations, unselected, unwired, skipped checks or changed executables. Verify real consumers and tested/untested scope. Early scans, rule self-checks or repeated same-source output cannot exclude other counterexamples.

Match local/CI inputs. Use one registered check command. Equal verdicts require identical effective inputs, scope, policy, executables, toolchain and environment, plus determinism. Local feedback, shallow checks or static shape cannot replace remote tests. Diagnose differences; local green alone cannot explain remote red.

Run real workflow events. For CI, permission, routing or gate edits, test applicable events: selected/unselected, reject/accept, success/failure, artifacts/caches. Pin run/event, entry workflow repo/path/revision, actual candidate/baseline and resolved reusable-workflow revision. Same-name green checks, branch filters or installation prove no candidate execution; local/shape tests cannot substitute.

Bound integration evidence. Preserve applicable protections/execution conditions; map each to delivery. Check first run after installation. Substitute events prove only actual versions, permissions and behavior; uncovered native routes remain gaps. Deliver candidate fixes; recheck changed/invalid scope. Stop with sufficient evidence; counts, time, old greens or titles prove no coverage/landing.

### Jobs and state

Separate domain and workflow. Identify chain inputs, outputs, writers and transitions. Report workflow completion and domain results separately; neither implies the other. Completion requires all necessary subitems/duties. Failure receipts, quarantine or record locations are no terminal success.

Snapshot mutable readings. Concurrent writes/mutations may give transient readings. Use fixed snapshots or verify before/after hashes match when control returns. Check collection conditions before blaming peers; do not archive temporary process snapshots.

Fix signal producers. Define instance, units, index, window and meaning; report failure. Historical totals cannot answer current windows; proxies cannot replace target readings. Completion needs real exits/artifacts; liveness/load needs suitable observations, not elapsed guesses. Report optional telemetry failure separately, preserving task exits; missing required contract inputs still fail explicitly. Fix misleading producers, not reader vigilance.

Keep jobs in host lifecycles. Beyond foreground budgets or for unknown durations, use available host jobs/sessions; retain handles/results. Launchers await real work, join all children in that lifecycle and propagate actual exits. Detached launch, process presence or launcher zero proves no task success.

Use one waiting channel. Use host completion notices, then read artifacts; no duplicate blocking wait. Else prefer native wait/watch. Only external state lacking primitives permits bounded polling: preset exits, event-appropriate intervals, time and key readings each round. Sleep proves no completion.

Bind query identity. Pin delivery targets; verify result/check/run ownership. Old snapshots cannot judge new targets. Missing/conflicting identity, partial errors, incomplete pages or timeout are not success. Distinguish unavailable, failed, unmerged and complete; read canonical results if wrappers collapse exits.

### Costs and cache

Improve using measured costs. Check input size, dependency scope and build, validation, CI and storage costs; report method, units, window and comparison basis, leaving unknowns explicit. Remove waste, poor representations and duplicate dependencies, then remeasure and verify real host consumption. Do not buy success with higher budgets, repeated runs, deleted necessary tests or weaker goals.

Stop redundant checks. Deliver after sufficient checks of the same effective inputs, absent new concerns. For change, failure or invalid evidence, identify affected duties/scope before targeted checks. Rerun success does not erase failure; preserve unaffected evidence.

Declare resource contracts. Before concurrency/residency/budget derivation, state quantities, units, domains, demand, limits, reserves and failure boundaries. Names do not define capacity problems. Do not mix units, requests/limits or enforced bounds/measured peaks. Missing data prevents derivation; never force one unit into insufficient capacity. Separate policy/derived values; justify exceptions/review conditions.

Separate capacity and observations. For static startup contracts, use declared capacity/fixed demand, never substitute or feed back load, free memory or transient RSS. Hold other inputs fixed; test determinism, domain boundaries and outputs as capacity changes. Dynamic feedback needs separate state, stability and failure contracts. Diagnostics are not automatically controls.

Check both cache layers. For slow builds/misses, inspect this run’s hit, key and seed/restore, then measure downstream increments, rebuild scope and costs. One layer cannot justify fixes. If warm caches remain costly, profile code, representations and dependencies; keep comparable before/after and negative results. Waiting, extra caches or reruns cannot hide poor representations.

Preserve performance comparisons. Compare source, workload, toolchain, hardware, cache and collection basis; report time, peak resources, rebuild volume, limits and needed negative findings. Reduce excess residency, poor structures and broad dependencies; remeasure. Local success/savings prove no remote cause; get remote evidence and exclude alternatives.

Reuse complete inputs only. Direct reuse of validated results needs determinism and identity covering all inputs affecting results or acceptance. Reassess after input, policy, executable, toolchain or environment changes. Hashes/hits prove neither complete inputs nor passed checks.

Validate seeds downstream. Approximate seeds may select broadly to avoid irrelevant misses; existing authoritative incrementality must check remaining delta, not custom heuristics. Analyze omitted-input false hits and irrelevant-input false misses. Narrow keys only with evidence of relevant fields/downstream contracts; never unconditionally drop file/commit identity.

Declare compatibility conditionally. Producer semantic versions need explicit justified contracts. Update versions/checks together for result or acceptance changes; continued compatibility needs evidence too. Machines infer no compatibility; missed updates reuse stale results. Never universally omit program, policy, toolchain or environment identity.

Caches cannot hide build failures. Reports/builds follow registered duties; hits still require selected incremental builds/checks. Selected build failures must exit nonzero, leave no success state. Omit resources only for explicit no-work cases; report hits cannot mask failure.

Run necessary queries. Run queries needed for later judgments; re-proving fixed bytes adds no evidence. Memoize by measured repetition/cost, not for one needed query. Retain needed inputs/results; do not rebuild old toolchains for mistaken historical questions. Check environment upgrades under current rules and explicit impact; Git bytes prove no semantics.
