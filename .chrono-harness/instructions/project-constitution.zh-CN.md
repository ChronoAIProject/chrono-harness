本宪法约束本仓维护者和 AI 的自迭代，解决“为了完成任务而不断改规则、扩大机制和消耗资源”的问题。唯一编辑源是 `.chrono-harness/instructions/project-constitution.zh-CN.md`；`docs/project-constitution.md` 是登记生成的阅读副本。当前用户指令优先于仓库规则。项目目标、分层法律和经济约束由此文件负责，产品行为仍由 SPEC 负责。

## 项目目标

chrono-harness 为接入仓库提供按明确依赖选择检查、核对真实结果和管理工作生命周期的工具。维护者、接入仓库和执行任务的 AI 是使用方。项目按以下顺序取舍：

1. **G0 用户结果**：完成当前授权的任务，提供正确、安全、可恢复且如实报告的行为。
2. **G1 合同兑现**：满足 SPEC、现役接口和明确在研目标，保护必要测试、输入、失败原件和迁移义务。
3. **G2 交付成本**：在满足 G0/G1 的可行方案中，选择全生命周期成本较低、足以完成任务的方案。

验收看实际结果：所选检查与两端登记对应，成功来自原始执行结果，未执行或缺证保持未知；交付和清理分别核实。规则数量、提交数量、测试数量和一次绿色检查均不能替代这些结果。优化的成本要可比较，收益要落到具体使用方。

## 宪法原则

- **目的约束手段**：自迭代可以修正手段，不能为了通过本轮检查自行缩小用户目标或删除必要验收。目标变化必须来自用户更正或独立的当前需求证据。
- **事实不能改写**：失败、已花成本和未知状态继续保留。新规则可以判定旧规则有错，但不能把没有发生的执行、交付或收益写成事实。
- **权威归属明确**：同一合同只在负责处维护，别名和投影回到登记源；既有规则先尝试，够用的工具先复用。
- **负担由修改者承担**：修改规则必须计入新增阅读、实现、迁移、验证、运行、存储、维护和恢复成本，不能把负担转移给未登记的下游。
- **资源有边界**：任务内自主修复，不新增人工批准关卡；到达资源或证据边界时停止该路线，保留结果，继续独立且已授权的工作。

## 分层法律

规则按它改变的含义定层级，不按文件名定层级；藏在 catalog、脚本或判官中的上位政策，仍按最高受影响层处理。

| 层 | 权威和负责位置 | 可以规定什么 | 修改义务 |
| --- | --- | --- | --- |
| L0 目标法 | 用户任务与 SPEC §1 的当前需求 | 使用方、结果、范围、验收和授权资源 | 说明独立需求依据，不能用本轮失败或成本超支为改目标作证 |
| L1 宪法 | 本文件 | 事实、自治、成本、改法权和权威边界 | 保全 L0，说明旧原则不足及替代原则的影响、验证和恢复 |
| L2 基本法 | SPEC 中的产品和接口合同 | 输入、行为、错误、证明、恢复与退役义务 | 更新实际使用方、登记和可观察验收 |
| L3 程序法 | 宿主工作指南、开发和交付规范 | 隔离、生成、检查、集成、交付和清理路径 | 沿现有唯一入口，按两端 DELTA 验证受影响流程 |
| L4 实施条例 | FILEMAP、项目操作、判官和 CI 登记及其实现 | 具体命令、依赖、限额、执行与判定 | 核对真实输入、输出、退出、选测和成本，不暗改上位合同 |

运行报告、成本报告和失败原件是事实证据，不是下一层可改写目标的法律。`CLAUDE.md` 的文字是源规则的投影，没有独立修法权。上位规则约束下位规则；发现冲突时只暂停依赖该冲突的工作，在负责处修复。影响越广，适用的验证和迁移成本越大，但不增加固定审批人数或全仓重跑。

## 经济法：规则修改必须支付什么

规则变更记录复用当前任务说明或 PR 正文，不另建永久价值台账。开始前写清目标、真实使用方、最高受影响层、固定基线、问题证据、保留现状及最小替代方案、预期结果、成本边界、验证、停止和恢复条件。收尾补上实际结果与采用、回滚或未知结论。

成本按真实单位分别记录：人或 AI 的投入时间、可取得的 token／调用／计费量，编译和检查的 CPU／墙钟时间、峰值内存、IO，保留字节及期限，以及新增规则、入口、依赖和下游迁移负担。`chrono-costs/v1` 的四维登记成本可以复用；声明估算、实测和未知分开，不能把 `null` 当零、把墙钟与 CPU 混算，或把并行峰值相加。

对以节约成本为目标的改法，在同一输入、单位和预先固定的使用窗口内比较：

```text
净节约 = 窗口内旧方案执行与保留成本 − 窗口内新方案执行与保留成本
         − 改法、迁移、验证、维护和恢复准备的新增成本
```

只有可相减的同种资源才能使用这个式子；不能把未知节约、未发生的未来使用或任意统一评分充当收入。净节约不为正时，不以“优化”为由采用。不同资源有取舍时逐项说明，不能用减少 IO 掩盖更多 CI、模型调用或下游维护成本。正确性、安全、恢复和用户明确要求的结果，可以按其必要性投入，仍须选择满足合同的最小方案并受预算约束，无须伪造货币收益。

### 预算与禁止自我融资

每条规则修改路线开始前固定投入上限、计量单位、来源和剩余额度。用户给出的资源上限优先；没有数值上限时，复用登记操作的时限和容量，并把取证限定在一个最小候选及本次明确影响的范围，不据此虚构整个任务的货币或 token 配额。无法取得必要上限时只阻断依赖它的扩张。必需验证和恢复也须占有预算，不能花尽资源后再省掉它们。

所有尝试，包括失败、放弃的候选、生成、改法自身及其验证，都从同一条路线累计扣账。改规则、换名字、换判官或开启新会话不清零；已花成本不是继续投入的收益。候选不能同时抬高约束自己的预算、改收益口径或延长观察窗口来证明自己划算。确有独立需求或环境证据要改上位政策时，固定新的依据和影响，保留原失败、原成本和原结论，沿对应层级验证；不借此把旧候选自动追认为通过。

### 未知、重试与停止

未知成本或收益先保持未知，不能支持正式扩张或声称净收益。允许在既有授权和预先声明的限额内做可逆的最小取证实验；实验的直接使用方是当前有明确验收的在研目标。限额不能在实验中自行提高，结果未建立时保留候选、不激活新增常态检查、依赖或保留负担。已有对象未知也不等于可以删除。

同一问题的一条有因果依赖的路线同时只推进一个未验候选；独立工作按原依赖并行。相同症状再次需要相同处理时，第二次优先修产生处，没有新证据不得第三次盲目重试。若修法又要求先修一层规则，合并回当前问题、重新核对总成本，不能递归制造新的治理任务或预算。

达到上限、必要结果不可取得、收益不足或当前方法已经满足目标时，停止该路线的新增投入。保全失败及恢复条件，报告缺口，继续独立工作。一次通过不抹去历史失败；也不为安心重复检查相同的有效输入。

## 改法与采用

按“需求→审计→必要重构→实现”推进。先用现有规则定位问题，再说明改法为何能保全上位目标；固定原先失败案例和必要行为，使用当前候选判官核验新行为、错误和边界。旧修订只读作事实数据，不执行旧判官。政策调整可使原来的错误拒绝不再适用，但必须说明独立需求依据和替代验收，不能只说新判官已通过。

修改宪法、判官、预算或本段修法规则本身，也须履行相同的成本、证据和迁移义务；不能在同一候选中删除这些义务来给自己豁免。规则和产品同改时，分别列出两组改动、前后影响和验证成本，给出可见提示，不增加人工放行环节。

规则源和投影使用宿主登记的 `instructions.generate`，验证使用 canonical check，集成和交付沿现有开发流程。采用要求是：满足当前目标、上位规则及预算；必需检查和实际使用方验收完成；成本结论与证据范围一致；迁移及恢复条件明确。任一条件缺失就报告未完成，不改写为成功。

| 场景 | 本宪法要求的结果 |
| --- | --- |
| 为使失败测试变绿而删去仍必要的测试 | 拒绝，以原目标和原失败为据修复 |
| 判官错误拒绝合法输入，有独立合同和反例 | 可修判官；支付回归、集成及使用方迁移成本 |
| 构建变快，但改法成本在声明窗口内收不回 | 不按节约成本采用；必要产品结果须另有明确依据 |
| 收益未知，拟新增常态 CI 检查 | 保留 proposed；只可做既有预算内的最小取证 |
| 预算耗尽，候选同时提高预算并改计量窗口 | 停止该路线，保留原账，不接受自我豁免 |
| 下层规则试图删除本宪法的改法义务 | 按 L1 变更处理，不能用 L4 自检自证生效 |

## 当前执行边界

本文件是对维护者和 AI 的明确约束，由现有生成器发布。`judge-cost` 目前只报告登记成本和未知坐标，不测量完整生命周期、不裁决收益、不强制预算或规则层级。经济判断由执行任务的 AI 根据当前证据负责，现有判官核对其已登记合同；本次不新增机器准入服务、判官或人工审批。生成成功、检查通过均不证明本宪法已被全面执行，完整机器治理仍未实现。
